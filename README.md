# worker-oauth

OAuth 2.1 authorization server running on Cloudflare Workers, backed by D1 (SQLite) and KV.

## Deploy

### Prerequisites

- [Node.js](https://nodejs.org) ≥ 22.13.1
- [Wrangler](https://developers.cloudflare.com/workers/wrangler/) v4 (installed by `npm ci`; use `npx wrangler`)
- A Cloudflare account authenticated with `wrangler login`

---

### 1. Install dependencies

```sh
npm ci
```

---

### 2. Create the D1 database

```sh
wrangler d1 create worker-oauth-db
```

Copy the `database_id` from the output and update `wrangler.jsonc`:

```jsonc
"d1_databases": [
  {
    "binding": "DB",
    "database_name": "worker-oauth-db",
    "database_id": "<paste-your-id-here>",
    "migrations_dir": "migrations"
  }
]
```

---

### 3. Create the KV namespaces

```sh
wrangler kv namespace create SESSIONS
wrangler kv namespace create OAUTH_KV
```

Copy each `id` from the output into `wrangler.jsonc`:

```jsonc
"kv_namespaces": [
  { "binding": "SESSIONS", "id": "<sessions-namespace-id>" },
  { "binding": "OAUTH_KV", "id": "<oauth-kv-namespace-id>" }
]
```

---

### 4. Set required secrets

The `POST /admin/setup-clients` endpoint is protected by a secret you set here:

```sh
wrangler secret put ADMIN_SECRET
# enter a strong random value when prompted
```

---

### 5. Update public configuration

In `wrangler.jsonc`, set `ISSUER` to your Worker's public URL and configure
the reCAPTCHA Enterprise site key used by `/login`:

```jsonc
"vars": {
  "ISSUER": "https://id.eventuai.com",
  "RECAPTCHA_SITE_KEY": "6LfhfwQtAAAAACRmsenmnvRlj6eNikByvdpDi_8J",
  "RECAPTCHA_PROJECT_ID": "<google-cloud-project-id>",
  "RECAPTCHA_MIN_SCORE": "0.5"
}
```

The site key and project ID are not secrets. Store the Google Cloud API key
used to create reCAPTCHA assessments as a Worker secret:

```sh
wrangler secret put RECAPTCHA_API_KEY
```

`POST /login` fails closed if `RECAPTCHA_PROJECT_ID` or
`RECAPTCHA_API_KEY` is missing.

---

### 6. Run database migrations

Apply to the **remote** D1 database:

```sh
npm run db:migrate
```

To apply locally (for `wrangler dev`):

```sh
npm run db:migrate:local
```

---

### 7. Deploy

```sh
npm run deploy
```

---

### 8. Register OAuth clients

`POST /admin/setup-clients` creates or updates up to 50 clients in one
call. Pass a JSON body with a `clients` array; the request must include the
`X-Admin-Secret` header.

**Register a confidential client** (e.g. the CMS Worker):

```sh
curl -X POST https://id.eventuai.com/admin/setup-clients \
  -H "X-Admin-Secret: <your-ADMIN_SECRET>" \
  -H "Content-Type: application/json" \
  -d '{
    "clients": [
      {
        "clientName": "Worker CMS",
        "redirectUris": ["https://cms.example.com/auth/callback"],
        "tokenEndpointAuthMethod": "client_secret_post"
      }
    ]
  }'
```

The response includes the generated `clientId` and `clientSecret`; store them
as the CMS `EVENTUAI_CLIENT_ID` var and `EVENTUAI_CLIENT_SECRET` secret.
Treat the response as sensitive and do not paste it into logs or source control.
New IDs and secrets are generated by the provider. To update an existing client,
supply its returned `clientId`; a `clientSecret` of at least 32 characters may
be supplied to rotate its secret. Omit `clientSecret` to preserve the existing one.

**Register a public (PKCE-only) client** (e.g. an SPA or CLI tool):

```sh
curl -X POST https://id.eventuai.com/admin/setup-clients \
  -H "X-Admin-Secret: <your-ADMIN_SECRET>" \
  -H "Content-Type: application/json" \
  -d '{
    "clients": [
      {
        "clientName": "My SPA",
        "redirectUris": ["https://app.example.com/callback"],
        "tokenEndpointAuthMethod": "none"
      }
    ]
  }'
```

**Register multiple clients at once** by adding more objects to the array.

Each client object supports:

| Field | Required | Description |
|-------|----------|-------------|
| `clientName` | Yes | Human-readable name; does not identify clients for updates |
| `redirectUris` | Yes | Allowed redirect URIs |
| `clientId` | No | Existing client ID to update; omit to create a new client |
| `clientSecret` | No | Existing confidential client secret rotation only (minimum 32 characters); omit on creation |
| `grantTypes` | No | Defaults to `["authorization_code", "refresh_token"]` |
| `tokenEndpointAuthMethod` | No | `"client_secret_post"`, `"client_secret_basic"`, or `"none"`; specify explicitly when creating a confidential client |

Automatic demo seeding has been removed. `ALLOW_DEMO_CLIENTS` has no effect.
Existing demo clients and their grants must be inventoried and revoked separately;
this update does not delete production data. Check each item's `status` in the
setup response: provider operations may fail individually.

## Routes

| Method | Path | Description |
|--------|------|-------------|
| `GET/POST` | `/login` | User login |
| `GET/POST` | `/register` | User registration |
| `GET` | `/dashboard` | Authenticated user dashboard |
| `GET/POST` | `/oauth/authorize` | Authorization / consent UI |
| `POST` | `/oauth/token` | Token endpoint |
| `GET` | `/oauth/userinfo` | Scope-filtered identity claims (Bearer token and `openid` required) |
| `POST` | `/logout` | End browser session (CSRF-protected form) |
| `GET` | `/.well-known/oauth-authorization-server` | RFC 8414 discovery |
| `POST` | `/admin/setup-clients` | Create/update OAuth clients (`X-Admin-Secret` header) |

## Supported scopes

`openid` · `profile` · `email` · `roles`

## Security and rollout

See [SECURITY_REVIEW.md](SECURITY_REVIEW.md) for findings, implemented controls,
remaining risks, and validation limits.

- Access tokens expire after 15 minutes; refresh tokens remain valid for 30 days.
- UserInfo returns profile, email, and roles only with their respective scopes.
  Emails are unverified (`email_verified: false`); roles come from current D1 data.
- All production cookies use `__Host-` names. Existing unprefixed cookies require
  another login. Pending authorization flows from older deployments must restart.
- New passwords require 15–128 characters. Login budgets are 8 attempts per
  IP/username, 15 per username, and 30 per IP per 15 minutes, including successful
  logins. Registration allows 5 attempts per IP per hour after input validation.
- Production reCAPTCHA always fails closed. Only localhost with
  `RECAPTCHA_ENFORCE=false` may bypass server verification; the stock browser UI
  still expects reCAPTCHA, so use configured test keys for browser testing.
- Forms accept URL-encoded data only. Request bodies are capped at 64 KiB.
- Run `npm ci`, `npm test`, `npm run typecheck`, and `npx wrangler deploy --dry-run`
  before deployment. Test client compatibility in staging before rollout.
